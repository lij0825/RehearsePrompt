# RehearsePrompt 종합 문제 해결 가이드 (Troubleshooting)

이 문서는 Windows 및 macOS 환경에서 **RehearsePrompt**를 사용하면서 발생할 수 있는 모든 오류와 예외 상황에 대한 원인 분석 및 단계별 해결 절차를 안내합니다.

각 문제 항목은 **증상, 가능한 원인, 확인 방법, 해결 방법, 그래도 안 될 때, 로그 수집 방법, 개인정보 주의사항**의 표준 규격을 따릅니다.

## 1. Windows 문제 해결

### <a id="w-01-설치-파일이-실행되지-않음"></a>1. 설치 파일이 실행되지 않음
- **증상**: 다운로드한 `setup.exe` 파일을 더블 클릭해도 반응이 없거나 마우스 커서 모래시계가 잠깐 뜬 뒤 사라짐.
- **가능한 원인**: 다운로드 중 파일 손상, 백신 프로그램의 차단, 32비트 Windows 환경(앱은 64비트 전용).
- **확인 방법**: 파일 크기가 약 83MB인지 확인하고, PowerShell에서 `Get-FileHash -Algorithm SHA256 .\setup.exe`를 실행하여 릴리스 해시와 대조.
- **해결 방법**: 다운로드를 완전히 다시 받거나, 백신의 실시간 감시 일시 중지 후 실행. 
- **그래도 안 될 때**: 무설치 포터블 파일(`RehearsePrompt-1.0.0-Windows-x64-portable.exe`)을 다운로드하여 실행.
- **로그 수집 방법**: `Win + R` > `eventvwr.msc` > [Windows 로그] > [응용 프로그램]에서 오류 이벤트 확인.
- **개인정보 주의사항**: 이벤트 뷰어 로그 캡처 시 Windows 사용자 계정명(예: `C:\Users\<이름>`)을 마스킹하십시오.

### <a id="w-02-smartscreen-경고"></a>2. SmartScreen 경고
- **증상**: 파란색 "Windows의 PC 보호" 창이 뜨며 실행 버튼이 보이지 않음.
- **가능한 원인**: 비영리 오픈소스 빌드로 고가의 상용 EV 인증서가 없어 Microsoft 평판 점수가 누적되지 않음.
- **확인 방법**: 다운로드 웹 주소가 공식 GitHub 리포지토리인지 확인.
- **해결 방법**: 창 본문의 **`[추가 정보]`** 링크 클릭 후 나타나는 **`[실행]`** 버튼 클릭.
- **그래도 안 될 때**: 공식 체크섬 해시가 일치하는지 확인하고, 사내 PC의 경우 IT 관리자에게 문의.
- **로그 수집 방법**: SmartScreen 화면 캡처 또는 Windows Defender 보안 기록 로그 확인.
- **개인정보 주의사항**: 경고 화면에 표시되는 파일 경로 내 개인 계정명을 가리십시오.

### <a id="w-03-webview2-없음"></a>3. WebView2 없음
- **증상**: 시스템에 WebView2 런타임이 없다는 오류 메시지가 뜰 것으로 걱정됨.
- **가능한 원인**: 구형 데스크톱 프레임워크와의 혼동.
- **확인 방법**: RehearsePrompt는 Electron 기반으로 **독립 최신 Chromium 엔진을 자체 내장**하고 있음.
- **해결 방법**: 별도의 WebView2 설치 없이 프로그램을 그대로 실행하시면 됩니다.
- **그래도 안 될 때**: 설치 폴더에 `d3dcompiler_47.dll`, `ffmpeg.dll` 파일이 정상 존재하는지 확인.
- **로그 수집 방법**: 설치 폴더 파일 목록 스크린샷 캡처.
- **개인정보 주의사항**: 파일 목록 캡처 시 상단 주소창의 개인 폴더 경로를 마스킹하십시오.

### <a id="w-04-앱이-실행-후-바로-종료됨"></a>4. 앱이 실행 후 바로 종료됨
- **증상**: 앱 창이 1초 정도 깜빡인 뒤 곧바로 닫힘.
- **가능한 원인**: GPU 가속 충돌, 손상된 로컬 JSON 설정 파일, 필수 종속 DLL 로드 실패.
- **확인 방법**: 명령 프롬프트(CMD)를 열고 `RehearsePrompt.exe --disable-gpu`로 실행하여 터미널 에러 확인.
- **해결 방법**: 그래픽 카드 드라이버 업데이트 또는 `%APPDATA%\rehearse-prompt` 폴더를 임시로 이름 변경 후 재실행.
- **그래도 안 될 때**: 관리자 권한으로 명령 프롬프트 실행 후 `sfc /scannow` 시스템 파일 무결성 검사.
- **로그 수집 방법**: `%APPDATA%\rehearse-prompt\logs` 폴더 내 로그 파일 확인.
- **개인정보 주의사항**: 로그 파일 공유 시 대본 텍스트 내용이나 PC 사용자명이 포함되지 않도록 확인하십시오.

### <a id="w-05-글자가-깨짐"></a>5. 글자가 깨짐
- **증상**: 대본 본문이나 메뉴의 한글이 네모(□)나 특수문자로 깨져 표시됨.
- **가능한 원인**: 외부에서 가져온 TXT 파일의 인코딩 불일치(EUC-KR vs UTF-8).
- **확인 방법**: 메모장에서 해당 텍스트 파일을 열고 우측 하단의 인코딩 표기가 `UTF-8`인지 확인.
- **해결 방법**: 메모장에서 [다른 이름으로 저장] 선택 후 인코딩을 **UTF-8**로 지정하여 저장 후 다시 불러오기.
- **그래도 안 될 때**: 대본 본문을 복사하여 웹 브라우저 주소창이나 메모장을 거쳐 순수 텍스트로 붙여넣기.
- **로그 수집 방법**: 깨진 텍스트 파일의 헤더 인코딩 확인.
- **개인정보 주의사항**: 대본 내용에 개인정보(주민번호, 전화번호, 이메일 등)가 포함되어 있다면 가려주십시오.

### <a id="w-06-한국어-입력-문제"></a>6. 한국어 입력 문제
- **증상**: 대본 편집창에서 한글 입력 시 자모가 분리되거나(`ㄱㅏㄴㅏㄷㅏ`), 마지막 글자가 중복 입력됨.
- **가능한 원인**: Windows IME(한글 입력기) 조합 버퍼와 React 가상 돔 간의 포커스 동기화 지연.
- **확인 방법**: Windows 설정 > [시간 및 언어] > [언어] > [한국어] 옵션의 Microsoft 입력기 버전 확인.
- **해결 방법**: Windows 설정의 한글 입력기 설정에서 **"이전 버전의 Microsoft IME 사용"** 켜기.
- **그래도 안 될 때**: 외부 메모장에서 작성 후 복사-붙여넣기(`Ctrl + V`)하여 대본 등록.
- **로그 수집 방법**: 입력기 버전 및 OS 빌드 정보 기록.
- **개인정보 주의사항**: 작성 중인 면접 내용이 유출되지 않도록 입력 화면 캡처 시 주의하십시오.

### <a id="w-07-마이크가-작동하지-않음"></a>7. 마이크가 작동하지 않음
- **증상**: 텔레프롬프터에서 마이크를 켜도 반응이 없고 말소리가 인식되지 않음.
- **가능한 원인**: Windows 마이크 개인정보 설정 차단, 잘못된 기본 입력 장치 선택, 마이크 물리 스위치 꺼짐.
- **확인 방법**: Windows 설정 > [개인 정보 및 보안] > [마이크]에서 "데스크톱 앱 마이크 액세스" 활성화 확인.
- **해결 방법**: 소리 설정에서 실제 사용하는 마이크(웹캠, 헤드셋)를 '기본 통신 장치'로 지정하고 마이크 볼륨을 80% 이상으로 상향.
- **그래도 안 될 때**: 음성 녹음기 앱으로 실제 소리가 녹음되는지 테스트하여 하드웨어 고장 여부 판별.
- **로그 수집 방법**: 소리 제어판 입력 탭의 마이크 볼륨 게이지 반응 확인.
- **개인정보 주의사항**: 마이크 테스트 시 주변 사생활 소리가 녹음되지 않도록 유의하십시오.

### <a id="w-08-카메라가-작동하지-않음"></a>8. 카메라가 작동하지 않음
- **증상**: 카메라 미리보기를 켜도 검은 화면만 나타나거나 장치 인식 실패 팝업이 뜸.
- **가능한 원인**: 웹캠을 다른 프로그램(Zoom, Teams 등)이 독점 사용 중, 렌즈 셔터 닫힘, 카메라 권한 차단.
- **확인 방법**: Zoom이나 다른 화상 회의 프로그램이 백그라운드에서 실행 중인지 작업 관리자 확인.
- **해결 방법**: 웹캠을 사용하는 다른 프로그램을 모두 끄고, 웹캠 상단의 물리적 프라이버시 셔터를 개방.
- **그래도 안 될 때**: 웹캠 USB를 다른 포트에 연결하거나 PC 재부팅.
- **로그 수집 방법**: 장치 관리자 > [카메라] 항목에서 드라이버 상태 확인.
- **개인정보 주의사항**: 웹캠 화면에 비치는 방 배경이나 얼굴이 외부에 노출되지 않도록 주의하십시오.

### <a id="w-09-음성 인식이 작동하지 않음"></a>9. 음성 인식이 작동하지 않음
- **증상**: 마이크 게이지는 움직이지만 내가 읽는 문장으로 스크롤이 내려가지 않음.
- **가능한 원인**: 언어 설정 불일치(영어 모드로 설정됨), 심한 주변 잡음, 대본과 실제 발화 단어의 큰 차이.
- **확인 방법**: 프롬프터 상단의 인식 언어가 한국어(`ko-KR`)로 선택되어 있는지 확인.
- **해결 방법**: 마이크를 입에 더 가깝게 배치하고, 또박또박 발음하며, 잡음이 적은 환경 조성.
- **그래도 안 될 때**: 방향키(`↑ / ↓`) 또는 `J / K` 키를 눌러 수동 스크롤 모드로 즉시 전환.
- **로그 수집 방법**: 개발자 도구 콘솔의 Web Speech API 이벤트 로그 확인.
- **개인정보 주의사항**: 테스트 발화 시 민감한 개인 정보(비밀번호, 주민번호 등)를 발음하지 마십시오.

### <a id="w-10-대본이-저장되지-않음"></a>10. 대본이 저장되지 않음
- **증상**: 대본을 작성하고 저장 버튼을 눌러도 앱을 껐다 켜면 사라져 있음.
- **가능한 원인**: `%APPDATA%` 폴더의 디스크 쓰기 권한 부족, 백신 프로그램의 파일 잠금, 디스크 공간 부족.
- **확인 방법**: 파일 탐색기에서 `%APPDATA%\rehearse-prompt` 경로로 이동하여 파일 생성이 되는지 확인.
- **해결 방법**: 디스크 여유 공간을 확보하고, 해당 폴더의 읽기 전용 속성을 해제.
- **그래도 안 될 때**: 상단 메뉴의 [대본 내보내기(JSON)] 기능을 통해 수동으로 바탕화면에 백업 파일 저장.
- **로그 수집 방법**: `scripts.json` 파일의 '수정한 날짜' 속성 확인.
- **개인정보 주의사항**: `scripts.json` 파일에는 사용자가 작성한 면접 대본이 들어있으므로 외부에 전달 금지.

### <a id="w-11-단축키가-작동하지-않음"></a>11. 단축키가 작동하지 않음
- **증상**: 스페이스바(일시정지)나 방향키를 눌러도 프롬프터가 멈추거나 움직이지 않음.
- **가능한 원인**: 프롬프터 창이 포커스를 잃었거나, 텍스트 입력 필드 안에 커서가 활성화되어 있음.
- **확인 방법**: 프롬프터 화면 빈 공간을 마우스로 한 번 클릭하여 창 포커스를 회복.
- **해결 방법**: 마우스 클릭으로 창을 활성화한 후 단축키 입력.
- **그래도 안 될 때**: 상단 도구 모음의 마우스 클릭 버튼을 직접 조작.
- **로그 수집 방법**: 키보드 입력 상태 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="w-12-항상 위 창이 작동하지 않음"></a>12. 항상 위 창이 작동하지 않음
- **증상**: 다른 프로그램을 클릭하면 프롬프터 창이 뒤로 숨어버림.
- **가능한 원인**: 핀(고정) 버튼이 꺼져 있거나, 다른 프로그램이 '최상위 관리자 권한'으로 실행 중임.
- **확인 방법**: 프롬프터 상단의 핀 아이콘이 활성화(파란색)되어 있는지 확인.
- **해결 방법**: 핀 아이콘을 다시 클릭하여 켜고, 다른 창(PowerPoint 등)을 일반 권한으로 실행.
- **그래도 안 될 때**: RehearsePrompt 창을 다른 창과 겹치지 않게 모니터 한쪽에 분할 배치.
- **로그 수집 방법**: 창 상태 속성 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="w-13-고 DPI에서 UI가 깨짐"></a>13. 고 DPI에서 UI가 깨짐
- **증상**: 4K 모니터나 150% 이상 배율 노트북에서 버튼이 겹치거나 글자가 흐릿해 보임.
- **가능한 원인**: Windows의 레거시 디스플레이 스케일링 보정 충돌.
- **확인 방법**: 바탕화면 우클릭 > [디스플레이 설정] > 배율 설정값(125%, 150%, 200% 등) 확인.
- **해결 방법**: RehearsePrompt 실행 파일 우클릭 > [속성] > [호환성] > [높은 DPI 설정 변경]에서 "높은 DPI 조정 재정의"를 '응용 프로그램'으로 설정.
- **그래도 안 될 때**: 디스플레이 배율을 100% 또는 200% 정수 배율로 조정.
- **로그 수집 방법**: 디스플레이 해상도 및 배율 스크린샷.
- **개인정보 주의사항**: 바탕화면 스크린샷 시 개인 파일명이나 사진을 가려주십시오.

### <a id="w-14-여러 모니터에서 창이 사라짐"></a>14. 여러 모니터에서 창이 사라짐
- **증상**: 다중 모니터를 쓰다가 보조 모니터를 분리했더니 프롬프터 창이 화면 밖으로 나가 안 보임.
- **가능한 원인**: 마지막 저장된 창 좌표가 연결 해제된 모니터 영역에 머물러 있음.
- **확인 방법**: 작업표시줄에는 앱 아이콘이 켜져 있으나 화면 어디에도 창이 보이지 않음.
- **해결 방법**: 작업표시줄의 앱 아이콘 클릭 후 `Win + Shift + 좌/우 방향키`를 눌러 주 모니터로 창 강제 이동.
- **그래도 안 될 때**: `Win + R` > `%APPDATA%\rehearse-prompt`에서 창 위치 설정 캐시 삭제.
- **로그 수집 방법**: 디스플레이 토폴로지 설정 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="w-15-제거 후 데이터가 남음"></a>15. 제거 후 데이터가 남음
- **증상**: 제어판에서 앱을 삭제했는데도 `%APPDATA%\rehearse-prompt` 폴더에 대본 파일이 남아 있음.
- **가능한 원인**: 실수로 인한 사용자의 중요한 면접 대본 손실을 방지하기 위한 의도된 보호 설계.
- **확인 방법**: 파일 탐색기에서 `%APPDATA%\rehearse-prompt` 폴더 잔존 여부 확인.
- **해결 방법**: 데이터까지 완전히 지우고 싶다면 해당 폴더를 수동으로 휴지통에 버리고 비우기.
- **그래도 안 될 때**: 사용자 프로필 캐시 정리 도구 활용.
- **로그 수집 방법**: 잔여 디렉터리 경로 확인.
- **개인정보 주의사항**: 영구 삭제 전 중요한 대본이 있다면 반드시 사전 백업 확인.

### <a id="w-16-업데이트 후 대본이 사라짐"></a>16. 업데이트 후 대본이 사라짐
- **증상**: 새 버전의 설치 파일을 깔았더니 작성했던 대본 목록이 비어 있음.
- **가능한 원인**: 설치 경로가 변경되었거나 다른 Windows 사용자 계정으로 설치됨.
- **확인 방법**: 기존 사용자 폴더(`C:\Users\<계정명>\AppData\Roaming\rehearse-prompt`)에 `scripts.json`이 있는지 검색.
- **해결 방법**: 기존 폴더의 `scripts.json`을 복사하여 현재 앱의 설정 경로로 가져오기.
- **그래도 안 될 때**: 사전에 내보내 둔 JSON 백업 파일 복원 기능 실행.
- **로그 수집 방법**: 디렉터리 내 백업 파일 탐색.
- **개인정보 주의사항**: 대본 백업 파일 복원 시 기존 임시 데이터가 덮어씌워질 수 있으니 주의.

## 2. macOS 문제 해결

### <a id="m-01-dmg가-열리지-않음"></a>1. DMG가 열리지 않음
- **증상**: 다운로드한 `.dmg` 파일을 더블 클릭해도 "이미지 마운트 실패" 또는 아무 반응이 없음.
- **가능한 원인**: 다운로드 도중 네트워크 끊김으로 파일이 불완전하게 저장됨.
- **확인 방법**: 터미널에서 `hdiutil chksum <파일명.dmg>` 실행하여 체크섬 오류 확인.
- **해결 방법**: 웹 브라우저 캐시를 비우고 공식 GitHub Releases에서 DMG 파일을 완전히 다시 다운로드.
- **그래도 안 될 때**: 터미널에서 `hdiutil attach <파일명.dmg> -verbose` 명령으로 강제 마운트 시도.
- **로그 수집 방법**: 터미널 마운트 에러 메시지 캡처.
- **개인정보 주의사항**: 터미널 프롬프트의 Mac 컴퓨터 이름과 사용자명을 마스킹하십시오.

### <a id="m-02-앱이-실행되지-않음"></a>2. 앱이 실행되지 않음
- **증상**: Dock에서 아이콘이 한 번 통통 튀다가 아무런 창도 열리지 않고 꺼짐.
- **가능한 원인**: 이전 프로세스의 비정상 잔류, 손상된 앱 캐시, 샌드박스 파일 충돌.
- **확인 방법**: 활성 상태 보기(Activity Monitor)에서 `RehearsePrompt` 프로세스가 남아 있는지 확인.
- **해결 방법**: 활성 상태 보기에서 잔류 프로세스 강제 종료 후 재실행.
- **그래도 안 될 때**: `~/Library/Application Support/rehearse-prompt` 폴더를 임시로 바탕화면으로 옮긴 후 실행.
- **로그 수집 방법**: [콘솔(Console)] 앱 열기 > 'crash reporter' 진단 보고서 확인.
- **개인정보 주의사항**: 크래시 리포트의 프로세스 메모리 덤프에 포함될 수 있는 개인 식별 정보 보호.

### <a id="m-03-미확인-개발자-경고"></a>3. 미확인 개발자 경고
- **증상**: "Apple에서 악성 소프트웨어가 있는지 확인할 수 없습니다" 경고창 표시.
- **가능한 원인**: 비영리 오픈소스 빌드로 유료 Apple Developer 공증 절차를 거치지 않은 개발 빌드임.
- **확인 방법**: 공식 배포 출처 URL 및 SHA-256 해시값 확인.
- **해결 방법**: Finder > [응용 프로그램]에서 **`Control` 키를 누른 상태로 앱 클릭 > [열기]** 선택 > 팝업에서 [열기] 클릭.
- **그래도 안 될 때**: 시스템 설정 > [개인정보 보호 및 보안] > 보안 섹션에서 **[확인 없이 열기]** 버튼 클릭.
- **로그 수집 방법**: 경고창 스크린샷 캡처.
- **개인정보 주의사항**: 화면 캡처 시 주변 열려있는 개인 문서 창을 가려주십시오.

### <a id="m-04-gatekeeper-차단"></a>4. Gatekeeper 차단
- **증상**: 앱이 손상되었으므로 휴지통으로 이동해야 한다는 알림이 뜸.
- **가능한 원인**: 인터넷에서 다운로드된 파일에 부여되는 격리 플래그(`com.apple.quarantine`)와 미공증 바이너리 충돌.
- **확인 방법**: 공식 릴리스 공지의 SHA-256 해시와 터미널 `shasum -a 256` 결과 대조.
- **해결 방법**: 파일 무결성이 확인된 경우 시스템 설정 > [개인정보 보호 및 보안]에서 공식 예외 승인.
- **그래도 안 될 때**: 회사 보안 관리자에게 오픈소스 도구 예외 승인 요청.
- **로그 수집 방법**: `spctl -a -v /Applications/RehearsePrompt.app` 터미널 출력.
- **개인정보 주의사항**: 보안 정책을 위반하는 무분별한 격리 해제는 피하십시오.

### <a id="m-05-마이크-권한-없음"></a>5. 마이크 권한 없음
- **증상**: 프롬프터 모드에서 마이크 아이콘을 켜도 목소리를 전혀 인식하지 못함.
- **가능한 원인**: 최초 실행 시 마이크 사용 권한 요청을 실수로 [허용 안 함]으로 눌렀음.
- **확인 방법**: 시스템 설정 > [개인정보 보호 및 보안] > [마이크] 목록에서 RehearsePrompt 확인.
- **해결 방법**: 시스템 설정 마이크 목록에서 RehearsePrompt 오른쪽 스위치를 **`[켬]`**으로 변경.
- **그래도 안 될 때**: 터미널에서 `tccutil reset Microphone com.rehearseprompt.app` 실행 후 앱 재실행.
- **로그 수집 방법**: 시스템 설정 마이크 권한 스크린샷.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-06-카메라-권한-없음"></a>6. 카메라 권한 없음
- **증상**: 카메라 미리보기 토글을 켜도 화면이 계속 검은색으로 표시됨.
- **가능한 원인**: 시스템 설정에서 카메라 접근이 차단되었거나, FaceTime 등 다른 앱이 카메라를 점유 중.
- **확인 방법**: 시스템 설정 > [개인정보 보호 및 보안] > [카메라] 확인.
- **해결 방법**: 카메라 권한을 허용하고, 카메라를 사용 중인 다른 프로그램을 종료.
- **그래도 안 될 때**: Mac 재부팅 후 카메라 미리보기 재시도.
- **로그 수집 방법**: 시스템 정보 > [카메라]에서 내장 FaceTime 카메라 인식 상태 확인.
- **개인정보 주의사항**: 카메라 화면에 비치는 개인 공간 노출 주의.

### <a id="m-07-권한을 허용했는데도 작동하지 않음"></a>7. 권한을 허용했는데도 작동하지 않음
- **증상**: 시스템 설정에 마이크가 켜져 있는데도 실제 발화 인식이 되지 않음.
- **가능한 원인**: 외부 오디오 인터페이스 또는 가상 오디오 드라이버(BlackHole 등)가 기본 입력으로 잡힘.
- **확인 방법**: 시스템 설정 > [사운드] > [입력] 탭에서 활성화된 입력 장치 확인.
- **해결 방법**: 'MacBook Pro 마이크' 또는 실제 사용 중인 외장 마이크를 선택하고 입력 음량을 70% 이상으로 조절.
- **그래도 안 될 때**: 앱을 완전히 껐다가(`Cmd + Q`) 다시 실행.
- **로그 수집 방법**: 사운드 입력 음량 게이지 반응 여부 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-08-음성 인식 네트워크 오류"></a>8. 음성 인식 네트워크 오류
- **증상**: 음성 인식이 잠시 동작하다가 네트워크 연결 오류 알림이 발생함.
- **가능한 원인**: Web Speech API 엔진이 온라인 음성 모델과 통신하는 과정에서 방화벽 또는 VPN에 의해 차단됨.
- **확인 방법**: 활성화된 사내 프록시, VPN, 또는 네트워크 필터링 소프트웨어 확인.
- **해결 방법**: VPN을 일시 해제하거나, 안정적인 Wi-Fi 네트워크로 전환.
- **그래도 안 될 때**: 프롬프터 속도 기반 자동 스크롤(WPM 모드) 또는 키보드 수동 모드로 연습 진행.
- **로그 수집 방법**: 브라우저 콘솔 네트워크 탭 에러 로그.
- **개인정보 주의사항**: VPN 연결 정보나 사내 IP 주소가 캡처에 포함되지 않도록 마스킹.

### <a id="m-09-Intel/Apple Silicon 호환 문제"></a>9. Intel/Apple Silicon 호환 문제
- **증상**: 앱 실행 시 속도가 매우 느리거나, 배터리가 빠르게 소모되거나, Rosetta 설치 안내창이 뜸.
- **가능한 원인**: Apple Silicon(M1~M4) Mac에 Intel 전용 x64 DMG를 잘못 설치함.
- **확인 방법**: 활성 상태 보기에서 RehearsePrompt 프로세스의 '종류'가 `Apple`인지 `Intel`인지 확인.
- **해결 방법**: 기존 앱을 삭제하고 공식 릴리스에서 **`arm64.dmg`** 파일을 다운로드하여 재설치.
- **그래도 안 될 때**: 내 Mac 정보에서 프로세서 종류 재확인.
- **로그 수집 방법**: 터미널 `uname -m` 및 `file /Applications/RehearsePrompt.app/Contents/MacOS/RehearsePrompt` 결과.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-10-Retina에서 UI가 흐림"></a>10. Retina에서 UI가 흐림
- **증상**: 고해상도 Retina 디스플레이에서 대본 글씨 테두리가 뿌옇게 보임.
- **가능한 원인**: 디스플레이 해상도 가상 배율 설정 또는 외장 모니터 미러링 시의 해상도 불일치.
- **확인 방법**: 시스템 설정 > [디스플레이]에서 해상도가 '기본값'으로 되어 있는지 확인.
- **해결 방법**: 디스플레이 설정을 Retina 기본 고해상도로 변경하고 앱 재실행.
- **그래도 안 될 때**: 앱 설정 메뉴에서 폰트 크기를 키우고 줄 간격을 1.5 이상으로 조정.
- **로그 수집 방법**: 디스플레이 정보 캡처.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-11-앱이 Applications 폴더에서 실행되지 않음"></a>11. 앱이 Applications 폴더에서 실행되지 않음
- **증상**: DMG 창에서는 실행되는데 응용 프로그램 폴더에 넣고 실행하면 오류가 발생함.
- **가능한 원인**: DMG 내에서 앱을 복사하지 않고 바로가기만 만들었거나, 복사 도중 전송이 중단됨.
- **확인 방법**: 응용 프로그램 폴더의 RehearsePrompt 크기가 약 250MB인지 확인(바로가기는 수 KB).
- **해결 방법**: 기존 불완전한 파일을 삭제하고 DMG에서 다시 드래그 앤 드롭으로 온전히 복사.
- **그래도 안 될 때**: 복사 완료 후 디스크 이미지를 반드시 추출(꺼내기)한 다음 실행.
- **로그 수집 방법**: Finder의 파일 정보(`Cmd + I`) 창 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-12-대본 저장 실패"></a>12. 대본 저장 실패
- **증상**: 대본을 저장하려고 하면 "저장 권한 오류"가 뜨거나 저장이 반영되지 않음.
- **가능한 원인**: `~/Library/Application Support` 디렉터리의 쓰기 권한이 잠겨 있음.
- **확인 방법**: Finder에서 해당 폴더로 이동하여 수동으로 텍스트 파일 생성이 가능한지 테스트.
- **해결 방법**: 해당 폴더 정보 창(`Cmd + I`)에서 [공유 및 사용 권한]을 '읽기 및 쓰기'로 복구.
- **그래도 안 될 때**: 설정 메뉴의 [대본 내보내기] 기능을 이용해 다운로드 폴더나 문서 폴더에 백업.
- **로그 수집 방법**: 터미널 `ls -ld ~/Library/Application\ Support/rehearse-prompt` 권한 확인.
- **개인정보 주의사항**: 대본 내용 유출 방지.

### <a id="m-13-단축키 충돌"></a>13. 단축키 충돌
- **증상**: 스페이스바나 `J / K` 키를 눌렀을 때 macOS 시스템 기능(Spotlight, 한영 전환 등)이 먼저 가로챔.
- **가능한 원인**: macOS의 글로벌 단축키 또는 타사 유틸리티(Alfred, Raycast 등)와 키 매핑 중복.
- **확인 방법**: 시스템 설정 > [키보드] > [키보드 단축키]에서 전역 단축키 중복 여부 확인.
- **해결 방법**: 프롬프터 창 내부를 마우스로 직접 클릭하여 포커스를 앱 내부로 고정.
- **그래도 안 될 때**: 충돌하는 타사 유틸리티의 전역 단축키를 다른 키로 변경.
- **로그 수집 방법**: 키보드 단축키 매핑 목록 확인.
- **개인정보 주의사항**: 특이사항 없음.

### <a id="m-14-앱이 외부 모니터에 표시되지 않음"></a>14. 앱이 외부 모니터에 표시되지 않음
- **증상**: Mac에 연결된 외장 모니터나 빔프로젝터로 프롬프터 창을 옮겼는데 화면이 보이지 않음.
- **가능한 원인**: macOS의 "디스플레이마다 별도의 Spaces 사용" 옵션으로 인한 가상 데스크톱 격리.
- **확인 방법**: Mission Control을 열어 프롬프터 창이 어느 Space 데스크톱에 있는지 확인.
- **해결 방법**: Mission Control 화면에서 프롬프터 창을 원하는 외장 모니터 데스크톱으로 마우스 드래그.
- **그래도 안 될 때**: 시스템 설정 > [데스크탑 및 Dock]에서 "디스플레이마다 별도의 Spaces 사용" 옵션 조정.
- **로그 수집 방법**: Mission Control 화면 캡처.
- **개인정보 주의사항**: 열려있는 다른 개인 작업 창 마스킹.

### <a id="m-15-앱을 삭제했는데 설정이 남음"></a>15. 앱을 삭제했는데 설정이 남음
- **증상**: 앱을 휴지통에 버리고 다시 깔았는데 이전 대본과 설정이 그대로 복원되어 있음.
- **가능한 원인**: macOS 표준 정책에 따라 앱 번들(.app)만 지우면 Application Support 데이터는 보존됨.
- **확인 방법**: `~/Library/Application Support/rehearse-prompt` 폴더 존재 확인.
- **해결 방법**: 완전 초기화를 원할 경우 Finder의 [폴더로 이동]을 통해 해당 폴더를 수동으로 휴지통에 버리기.
- **그래도 안 될 때**: 삭제 전 중요한 대본이 있다면 반드시 JSON 백업을 먼저 생성.
- **로그 수집 방법**: 디렉터리 경로 확인.
- **개인정보 주의사항**: 대본 삭제 시 복구가 불가능하므로 중요 데이터 백업 필수.

## 3. 화면 공유 관련 고지 및 문제 해결

### <a id="s-01-텔레프롬프터가-공유-화면에-보임"></a>1. 텔레프롬프터가 공유 화면에 보임
- **증상**: Zoom이나 Teams 회의 중 상대방에게 내 텔레프롬프터 화면이 그대로 보여서 당황함.
- **가능한 원인**: 회의 프로그램에서 '전체 화면(Desktop/Screen)' 공유 모드를 선택했기 때문.
- **확인 방법**: 화상 회의 프로그램의 초록색 공유 테두리가 화면 전체를 감싸고 있는지 확인.
- **해결 방법**: 화상 회의의 [화면 공유] 메뉴에서 전체 화면 대신 발표 슬라이드 등 **특정 창(Window)만을 지정하여 공유**.
- **그래도 안 될 때**: 다중 모니터를 사용하여 한쪽 모니터에는 프롬프터를 띄우고, 다른 쪽 모니터 화면만 공유.
- **로그 수집 방법**: 화상 회의 공유 모드 설정 창 확인.
- **개인정보 주의사항**: 화면 공유 중 개인 메신저나 이메일 창이 함께 공유되지 않도록 사전 정리.

### <a id="s-02-특정 창 공유와 전체 화면 공유 차이"></a>2. 특정 창 공유와 전체 화면 공유 차이
- **증상**: 창 공유와 전체 화면 공유의 정확한 차이와 프롬프터 노출 여부를 알고 싶음.
- **가능한 원인**: 화상 회의 도구의 화면 전송 방식에 대한 이해 부족.
- **확인 방법**: 
  - **전체 화면 공유 (Entire Screen)**: 모니터에 뜨는 모든 창(텔레프롬프터 포함)이 청중에게 100% 실시간 전송됨.
  - **특정 창 공유 (Window Share)**: 오직 선택한 특정 프로그램(예: PPT 슬라이드 쇼)만 전송되며, 그 위에 겹쳐진 프롬프터 창은 상대방 화면에 보이지 않을 수 있음.
- **해결 방법**: 리허설 시 동료와 함께 모의 회의를 켜고 내 화면이 어떻게 보이는지 사전 테스트 진행.
- **그래도 안 될 때**: 혼자서 화상 회의를 개설하고 녹화 기능을 켜서 실제 녹화본을 재생해 검증.
- **로그 수집 방법**: 회의 녹화 테스트 영상 확인.
- **개인정보 주의사항**: 녹화 영상 보관 시 개인 정보 보호.

### <a id="s-03-화면 공유 상태에서 앱을 숨기지 않는 이유"></a>3. 화면 공유 상태에서 앱을 숨기지 않는 이유
- **증상**: 다른 부정행위 도구들처럼 화면 공유에서 자동으로 투명하게 숨겨지는 기능이 왜 없는지 궁금함.
- **가능한 원인**: RehearsePrompt의 개발 목적과 윤리적 설계 원칙에 대한 확인 필요.
- **확인 방법**: 본 프로그램은 시험 부정행위나 감시 우회용이 아닌 **순수 발표·스피치 훈련 도구**임.
- **해결 방법**: 당당한 시선 처리와 유창한 말하기 역량을 기르기 위한 정직한 연습 목적으로만 활용하십시오.
- **그래도 안 될 때**: 실제 공식 시험이나 면접에서는 주최 측의 엄격한 규정과 안내를 준수하십시오.
- **로그 수집 방법**: 앱의 윤리적 선언문(`docs/SCREEN_SHARING_NOTICE_KO.md`) 확인.
- **개인정보 주의사항**: 규정을 위반한 부정 사용으로 인한 불이익은 전적으로 사용자 본인에게 있습니다.

### <a id="s-04-화면 공유 기능을 우회하지 않는다는 고지"></a>4. 화면 공유 기능을 우회하지 않는다는 고지
- **증상**: 안티치트나 시험 감독 시스템, 화면 캡처 회피 API가 탑재되어 있는지 확인하고 싶음.
- **가능한 원인**: 보안 감사 및 프로그램 투명성 검증 필요.
- **확인 방법**: 소스 코드 및 바이너리 검증 결과 `SetWindowDisplayAffinity`, `WDA_EXCLUDEFROMCAPTURE` 등 감시 우회 API 0건.
- **해결 방법**: RehearsePrompt는 투명한 표준 OS 그래픽 계층에서 동작하므로 감시 시스템을 기만하거나 회피하지 않습니다.
- **그래도 안 될 때**: 사내 보안팀이나 면접 주관사에 본 소프트웨어의 오픈소스 코드 및 무결성 보고서를 제출하여 사전 승인 요청.
- **로그 수집 방법**: `artifacts/verification-report.md`의 윤리적 비우회 감사 보고서 확인.
- **개인정보 주의사항**: 공식 평가 환경에서는 항상 주최 기관의 가이드라인을 최우선으로 따르십시오.
