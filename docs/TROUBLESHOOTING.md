# RehearsePrompt 문제 해결 가이드 (Troubleshooting Guide)

RehearsePrompt 사용 중 발생할 수 있는 주요 증상별 원인과 해결 방법을 안내합니다.

---

## 1. 마이크 및 음성 인식 관련 문제

### 증상 1: "마이크 장치를 찾을 수 없습니다" 또는 권한 거부 오류
- **원인**:
  1. PC에 물리적 마이크(내장 마이크, 웹캠 마이크, 헤드셋 등)가 연결되어 있지 않음
  2. Windows 또는 macOS 운영체제 설정에서 앱의 마이크 접근 권한이 차단됨
- **해결 방법**:
  - **Windows**: `Windows 설정 > 개인 정보 및 보안 > 마이크`에서 "마이크 액세스"와 "데스크톱 앱의 마이크 액세스 허용"이 모두 `켬`으로 되어 있는지 확인합니다.
  - **macOS**: `시스템 설정 > 개인정보 보호 및 보안 > 마이크`에서 RehearsePrompt가 체크되어 있는지 확인합니다.
  - 헤드셋/웹캠 USB를 분리했다가 다시 연결한 후 앱을 재시작합니다.

### 증상 2: 말을 해도 프롬프터가 움직이지 않거나 엉뚱한 문장으로 튈 때
- **원인**:
  1. Web Speech API 엔진이 주변 소음(에어컨, 키보드 타건음)을 사용자의 목소리로 오인식
  2. 너무 빠른 발음이나 불분명한 발음으로 인해 단어 일치 점수가 기준치 미달
  3. 인터넷 연결 단절 (Chromium 기본 Web Speech API는 온라인 음성 모델을 참조할 수 있음)
- **해결 방법**:
  - **수동 위치 보정**: 잘못 이동한 경우 마우스로 읽고자 하는 문장을 직접 클릭하면 기준 위치가 즉시 강제 동기화됩니다.
  - **속도 모드(WPM) 병행**: 주변 소음이 심하거나 네트워크 연결이 불안정할 경우 프롬프터 상단의 [속도 모드]를 활성화하여 일정한 템포(예: 160 WPM)로 스크롤하는 것을 권장합니다.
  - 마이크와의 거리를 15~20cm 정도로 유지하고 조용한 환경에서 연습해 주세요.

## 2. 화면 및 스크롤 관련 문제

### 증상 3: 스페이스바를 눌러도 대본이 스크롤되지 않음
- **원인**: 대본 본문 입력 영역에 마우스 커서(포커스)가 들어가 있거나, 스크롤 속도가 너무 낮게(0 WPM) 설정됨
- **해결 방법**:
  - 화면 상단의 **[프롬프터 시작]** 버튼을 눌러 프롬프터 전용 뷰로 진입했는지 확인합니다. (대본 편집 모드에서는 스페이스바가 공백 입력으로 동작합니다.)
  - 프롬프터 화면 상단의 속도 슬라이더가 100~200 WPM 사이로 설정되어 있는지 확인합니다.
  - 키보드 `Space` 키를 눌러 재생(Play) 상태로 전환되었는지 확인합니다.

### 증상 4: 고해상도(4K / QHD) 모니터에서 글씨가 너무 작거나 흐리게 보임
- **원인**: Windows 배율(DPI Scaling) 설정 불일치
- **해결 방법**:
  - RehearsePrompt 창 우측 상단의 **[글자 크기(Font Size)]** 슬라이더를 32px ~ 42px 이상으로 확대합니다.
  - Windows의 경우 `RehearsePrompt.exe` 우클릭 > `속성` > `호환성` > `높은 DPI 설정 변경` > `높은 DPI 조정 재정의(응용 프로그램)`를 체크합니다.

## 3. 설치 및 보안 백신(SmartScreen) 관련 문제

### 증상 5: 설치 프로그램 실행 시 "Windows의 PC 보호" 창이 나타남
- **원인**: 비영리 오픈소스 배포판 특성상 마이크로소프트의 유료 코드서명 인증서(EV Code Signing)가 등록되지 않아 발생하는 일반적인 보안 경고입니다.
- **해결 방법**:
  - 팝업 좌측의 **[추가 정보]**를 클릭한 후, 우측 하단의 **[실행]** 버튼을 클릭하여 정상 설치를 진행합니다.

### 증상 6: 백신(V3, 알약, Defender)에서 오진(False Positive)으로 파일 격리
- **원인**: Electron 패키징 파일(`win-unpacked/elevate.exe` 등 시스템 설치 도구)에 대한 백신 휴리스틱 엔진의 과도한 오탐
- **해결 방법**:
  - RehearsePrompt 공식 GitHub Release에서 제공하는 무결성 검증 체크섬(`SHA256SUMS.txt`)과 다운로드한 파일의 해시값을 비교합니다.
  - 사용 중인 백신의 실시간 검사 예외 폴더에 RehearsePrompt 설치 경로를 등록합니다.

---

## 4. 데이터 저장 및 손상 복구 문제

### 증상 7: 대본이 사라졌거나 잘못 삭제했을 때
- **해결 방법**:
  1. 좌측 사이드바 하단의 **[휴지통]** 탭을 클릭하여 삭제된 대본이 있는지 확인하고 **[복구]**를 누릅니다.
  2. 시스템 비정상 종료로 JSON 파일이 손상된 경우, 데이터 디렉터리 내 자동 백업 파일을 확인합니다:
     - Windows: `%APPDATA%\RehearsePrompt\storage\`
     - macOS: `~/Library/Application Support/RehearsePrompt/storage/`
     - 해당 폴더에 보관된 백업 파일(`scripts.json.bak`)의 확장자를 `scripts.json`으로 교체한 뒤 앱을 재실행합니다.
